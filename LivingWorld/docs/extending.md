# как расширять проект

## новый вид ягоды

1. добавь запись в `Definitions/Data/items.json`: уникальный id, название, существующий material, масса, объем, калории, вода, срок хранения.
2. добавь растение в `plants.json`: `kind: "bush"`, `product` со ссылкой на новый предмет, урожай, сроки роста, климатические пределы и цвета.
3. `spawnWeight` управляет частотой появления среди подходящих видов, `optimalTemperature` — предпочтительным климатом.
4. запусти проверки определений, затем создай новый мир. старый мир не пересоздает существующую растительность при загрузке.

генератор растений, рост, сбор, физическое поднятие и еда используют эти определения. переписывать ai для нового вида с теми же свойствами не нужно. новая механика яда или новый способ распространения потребует отдельной логики.

## новая одежда

добавь `ItemDefinition` с материалом, слотами, покрытием, толщиной, удобством, массой и прочностью. при необходимости добавь рецепт и источник сырья. температурная система и действие надевания читают свойства определения. не вводи отдельный флаг «теплая вещь».

## новая механика

например, стресс:

1. создай `StressComponent` с данными и уникальным атрибутом `Component("Stress")`.
2. создай `StressSystem`, реализующий `ISimulationSystem`.
3. зарегистрируй систему в подходящем месте `SimulationSession.Systems`.
4. добавь компонент при создании npc в `NpcFactory`.
5. добавь миграцию для старых сохранений либо явную инициализацию отсутствующего компонента при обновлении формата.
6. при необходимости добавь оценщик `ISituationEvaluator`, который учитывает стресс. остальные системы подключай только там, где есть реальное влияние.
7. добавь проверку взаимодействия с существующей физиологией и сохранением.

новые типы компонентов автоматически попадают в снимок через атрибут. это не отменяет необходимости продумать, как старые сущности получат новое состояние.

## новое действие

создай отдельный файл, наследуй `SimAction` и зарегистрируй экземпляр в `ActionRegistry` через `SimulationSession`.

`Options` получает личные знания и наблюдения. он описывает прогноз: предусловия, изменения фактов, длительность, расстояние и риск. `CanExecute` проверяет реальные условия. `Execute` применяет изменения, расходует предметы и публикует события. взрослые виды работ выставляют `RequiresWork` и проверяют физическую пригодность при выполнении.

для конкурентной цели используй `Exclusive`. для длительного участия другого человека — `EngagesTarget`. эффекты предметов называются `item:<definition id>`: по ним планировщик автоматически рассчитывает изменение переносимого веса и объема.

если действие меняет позицию или удаляет сущность, обновляй пространственный индекс. если меняет стены, лед или проходимость, увеличивай ревизию навигации. если меняет замкнутость пространства — отмечай `RoomsDirty`.

## новые социальные последствия

публикуй событие совершенного действия. подписчик отношений может изменить направленные значения, подписчик памяти — записать факт, подписчик навыков — начислить опыт. не помещай все последствия в один обработчик npc.

## изменения сохранений

сейчас используется версия 1. при несовместимом изменении увеличь `CurrentVersion`, создай реализацию `ISaveMigration` и зарегистрируй ее у `SaveService`. миграция должна менять json и версию без потери id и родственных связей. проверь загрузку реального сохранения предыдущей версии.

новые определения могут добавляться без изменения старых контрактов. изменение существующих материалов, рецептов или видов требует миграции их отпечатков и затронутого состояния. порядок ключей внутри сложных словарей определений стоит сохранять: отпечаток строится из их сериализуемого представления.

## перед изменением производительности

сначала измерь headless-прогон и вкладку систем. тяжелый поиск пути, планирование и восприятие имеют разные причины нагрузки. меняй конкретную систему, сохраняй порядок событий и проверяй сохранение / продолжение. многопоточное обновление общего реестра сейчас не поддерживается.

## обычный цикл проверки

```bash
dotnet build LivingWorld.csproj
dotnet run --project Tests/LivingWorld.Tests.csproj -c Release
dotnet run --project Headless/LivingWorld.Headless.csproj -c Release -- --seed 1847 --ticks 1440
```

после этого открой godot, проверь отрисовку, выбор npc, паузу, скорость и сохранение. для изменений интерфейса проверяй размер окна 1000 × 650 и стандартный 1440 × 900.
