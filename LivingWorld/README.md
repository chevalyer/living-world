# living world

версия: **0.8.0-alpha**

2d-симуляция для **godot 4.7.1 .net + c#**, собранная по приложенному плану. мир живет по фиксированным тикам, а персонажи выбирают действия через оценку ситуации и поиск цепочки действий.

это обновление развивает v0.7.0-alpha без отката его систем: добавляет процедурные дома, физические грядки, отдельные семена, новые культуры, еду и одежду, фиксированные 7×7-границы поселений и расширенный набор инструментов. существующие мебель, рабочие объекты, производство и улучшенный npc ai из v0.7 сохранены. кроме того, дома и производство остаются на физическом слое симуляции: npc строят физическую мебель и рабочие объекты, используют кровати, семейные сундуки, общественные рабочие места и колодцы, а рецепты связываются с возможностями вроде `workbench`, `textile`, `metalworking` и `baking`. одновременно исправлены найденные ошибки поведения npc, выбора населения нового мира и генерации названий поселений.

## запустить игру

1. установи **godot 4.7.1 с пометкой .net**: [официальная страница версии](https://godotengine.org/download/archive/4.7.1-stable/).
2. установи **.net 8 sdk**, именно sdk: [скачать](https://dotnet.microsoft.com/en-us/download/dotnet/8.0).
3. распакуй весь архив в обычную папку.
4. в godot нажми **import**, выбери `project.godot` и открой проект.
5. нажми **build** в редакторе, затем **f5**.

при первой сборке нужен интернет для пакета `Godot.NET.Sdk/4.7.1`. дополнительные картинки, шрифты, сервер и api-ключи не нужны: пиксельные объекты рисуются внутри godot.

поддержка c# требует версии движка .net и отдельного sdk — это описано в [документации godot](https://docs.godotengine.org/en/4.7/tutorials/scripting/c_sharp/c_sharp_basics.html).

начальный мир: сид `1847`, карта `128 × 128`, 14 взрослых жителей. вверху можно создать другой мир. на экране нет заданий игроку: это режим наблюдения за симуляцией.

### запуск из терминала

windows, если godot добавлен в path:

```bat
run.bat
```

либо передай путь к исполняемому файлу godot .net:

```bat
run.bat "C:\Tools\Godot\Godot_v4.7.1-stable_mono_win64.exe"
```

linux / macos:

```bash
bash run.sh /полный/путь/к/godot
```

на macos путь обычно указывает на исполняемый файл внутри `.app/Contents/MacOS/`. сначала установи .net sdk под архитектуру своего компьютера.

## управление

| действие | кнопка |
| --- | --- |
| передвинуть камеру | wasd, стрелки или средняя кнопка мыши |
| масштаб | колесо |
| вся карта | f |
| вернуться к старту | home |
| выбрать жителя / клетку | левая кнопка мыши |
| убрать выбор | esc |
| пауза | пробел |
| скорость 1× / 4× / 12× / 32× | 1 / 2 / 3 / 4 |
| поиск жителя | ctrl+f |
| известные ресурсы и маршрут | f2 |
| следующий слой карты | f3 |
| скрыть / показать весь интерфейс | h |
| сохранить в выбранный слот | f5 |
| загрузить выбранный слот | f9 |

слева находятся поиск жителей и список обнаруженных поселений, справа — инспектор жителя, поселения, мира и diagnostics. слой карты можно переключать между обычным видом, границами поселений, тропами, плодородием, комнатами и мебелью/рабочими объектами. клавиша `H` скрывает панели, подписи выбора и debug-overlay, не останавливая симуляцию.

скорость 1× задаёт 24 игровых минуты в секунду, 32× — 768: целевой игровой день проходит за 1,875 секунды. интерфейс показывает и заданную, и фактическую скорость. если компьютеру не хватает производительности, фактическая скорость снижается; тики не пропускаются. масштаб и положение камеры меняют только изображение: все жители продолжают жить по тем же правилам.

доступны три слота сохранений. слот 1 сохраняет совместимость со старым `world.save.json`, слоты 2 и 3 используют отдельные файлы. они находятся в стандартной папке данных godot для приложения `Living World`; на windows: `%APPDATA%/Godot/app_userdata/Living World/`. запись атомарная через временный файл, а при ошибке загрузки текущий мир остается открытым.

## что включено

- отдельные сборки definitions, simulation, infrastructure, presentation; еще headless и tests;
- генерация высот, геологии, водосбора, рек, озер, климата, биомов и растительности;
- типизированные компоненты, стабильные идентификаторы и отдельные потоки случайности;
- календарь, погода, рост растений, порча еды, намокание одежды, снег и лед;
- физиология, инвентарь с массой и объемом, предметы с состоянием;
- ограниченное восприятие, память, обучение, utility-оценки и планировщик;
- отдельные модули действий: добыча, еда, производство, стройка, общение, обмен и другие;
- стены, двери, пол, крыша, определение замкнутых помещений и костры;
- data-driven facilities: кровати, семейные сундуки, верстаки, ткацкие станки, ручные мельницы, горны, печи и колодцы;
- семейное и общественное использование facilities: личное хозяйство не превращается в глобальный инвентарь, а общественными рабочими местами могут пользоваться другие семьи;
- производственные цепочки `бревно → доски → мебель`, `волокно → ткань → одежда`, `зерно → мука → хлеб`, `руда → слиток → железный инструмент`;
- направленные отношения, партнерство взрослых, беременность, рождение, уход, взросление и смерть;
- вытаптывание растительности и тропы, которые влияют на стоимость пути;
- автоматическое обнаружение поселений по завершённым домам, их названия, границы и статистика;
- поиск жителей, навигация к поселениям и информационные слои карты, включая слой рабочих объектов;
- используемые инструменты, материалы, еда и семена отображаются в руках npc во время соответствующего действия;
- сохранение состояния ядра и загрузка, включая планы, память, rng и незавершенные действия.

имена, фамилии и названия поселений собираются из случайных гласных и согласных по правилам `Definitions/Data/Names/names.json`. для поселений больше нет словарей корней вроде «свет-», «ветр-» или окончаний «-град». одинаковый seed и якорный дом дают одинаковое фонетическое название. ребёнок наследует фамилию матери без изменения окончания.

у кустов разные виды: на кусте малины растет малина, на кусте черники — черника. урожай берется из определения вида. новый вид можно добавить через json; выбор растительности использует подходящие определения и их веса.

## проверить ядро без godot

```bash
dotnet run --project Tests/LivingWorld.Tests.csproj -c Release
```

это самостоятельный набор проверок с кодом выхода 0 при успехе. он не требует xunit и внешних тестовых пакетов. команда `dotnet test` для него не используется.

прогнать сутки симуляции и получить отчет, сохранение и svg-карту:

```bash
dotnet run --project Headless/LivingWorld.Headless.csproj -c Release -- --seed 1847 --size 128 --npcs 14 --ticks 1440 --save artifacts/day-one.save.json --map artifacts/map.svg --json artifacts/metrics.json
```

полная локальная проверка: `scripts/check.bat` или `bash scripts/check.sh`. если установлен python 3, структурные проверки отдельно запускаются командой `python scripts/check_sources.py`. GitHub Actions дополнительно собирает проект, запускает regression tests, суточный и недельный headless-прогоны и основную Godot-сцену в headless-режиме. длинные multi-seed и lifecycle soaks запускаются для финальной проверки обновления или вручную.
